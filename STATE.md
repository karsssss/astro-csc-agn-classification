## 2. Label logic location

Everything lives in **`src/preprocessing.py::build_labels(df)`** (lines
89-147). One function, not split across a `features/labels.py`-style
module as `PLAN.md` had proposed.

- `agn_positive` = `df[["xray_agn", "optical_agn", "ir_agn"]].any(axis=1)` (line 108)
- `agn_negative` = `df["non_agn"]`, then corrected (line 109, 111)
- `label_conflict` = `agn_positive & agn_negative` **before** the correction (line 110)
- `silver_score` / `silver_agn` — weighted heuristic (Mateos wedge 0.35, CSC
  power-law fit presence 0.35, top-quintile legacy X-ray/optical ratio 0.15,
  high-quality `combo_Z` 0.15), thresholded at `>= 0.01` and gated on
  `~agn_positive & ~agn_negative` (lines 129-139)
- `label_3class` via `np.select` on `[agn_positive, agn_negative, silver_agn]`
  → `[2, 0, 1]`, default `-1` (lines 141-145)

**Priority rule, quoted verbatim (lines 108-111):**

```python
df["agn_positive"] = df[agn_cols].any(axis=1)
df["agn_negative"] = df[neg_col]
df["label_conflict"] = df["agn_positive"] & df["agn_negative"]
df["agn_negative"] = df["agn_negative"] & ~df["agn_positive"]  # priority to positive labels
```

Docstring (lines 94-96): *"Priority is given to positive AGN labels over
`non_agn` when both are set (`label_conflict` flags the overlap) — this is
load-bearing for downstream model training, see CLAUDE.md."*

**Matches root `CLAUDE.md`** ("Label taxonomy" section) verbatim in
substance: *"`agn_negative` — confirmed non-AGN, with positive labels taking
priority when both are set (`label_conflict` flags the overlap)"*. Confirmed
consistent — no drift between code and doc on this specific rule.

`combo_Z` is numeric-non-null for 32,260 rows, of which 31,773 are strictly
positive (487 rows have `combo_Z` at or near zero — small negative/
near-zero values like `-1.38e-04`, consistent with DESI redshift-fit noise
around z≈0, not a data-quality flag by themselves).
`to_bool_safe(high_quality_z)` is `True` for 27,822 rows, and
`(combo_Z > 0) & high_quality_z` holds for **27,335 rows** — this is the
set `build_labels` itself uses for the "high-quality redshift" silver-score
component (see §2), so it's confirmed as the pipeline's own choice, not
just my inference.

`Rec_Z` is the one loose end here — I don't know what it is or which
survey it comes from; not in `CLAUDE.md`'s documented column list.
